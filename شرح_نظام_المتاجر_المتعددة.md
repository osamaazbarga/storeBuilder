# 🏪 شرح نظام المتاجر المتعددة (Multi-Tenant)
## كيف يعمل نظام Subdomains في تطبيقك

---

## 🎯 **الهدف:**

تريد أن يكون لكل متجر رابط خاص به:
- **المنصة الرئيسية:** `https://dokan.shop`
- **متجر 1:** `https://store1.dokan.shop`
- **متجر 2:** `https://store2.dokan.shop`
- **متجر محمد:** `https://mohammed.dokan.shop`

---

## ❌ **المشكلة التي واجهتها:**

عندما حاولت فتح:
```
https://store1.store-builder-git-dev-osamaazbargas-projects.vercel.app
```

**النتيجة:** لم يعمل! لماذا؟

### **السبب:**

1. **Vercel لا يدعم Wildcard Subdomains تلقائياً**
   - يعني: لا يمكنك استخدام `*.dokan.shop` مباشرة
   - يجب إضافة كل subdomain يدوياً

2. **الكود لم يكن جاهزاً**
   - لم يكن هناك كود يكتشف الـ subdomain
   - لم يكن هناك كود يحمّل بيانات المتجر بناءً على الـ subdomain

---

## ✅ **الحل الذي تم تطبيقه:**

### **1. في الفرونت إند (Angular):**

#### **أ. DomainService - خدمة جديدة:**
هذه الخدمة تكتشف تلقائياً نوع الرابط:

```typescript
// مثال:
const domainInfo = domainService.getDomainInfo();

// إذا فتحت: https://dokan.shop
// النتيجة:
{
  isMainPlatform: true,  // ✅ هذه المنصة الرئيسية
  isSubdomain: false,
  storeIdentifier: null
}

// إذا فتحت: https://store1.dokan.shop
// النتيجة:
{
  isMainPlatform: false,
  isSubdomain: true,     // ✅ هذا subdomain
  storeIdentifier: "store1"  // ✅ اسم المتجر
}

// إذا فتحت: https://mystore.com (دومين خاص)
// النتيجة:
{
  isMainPlatform: false,
  isCustomDomain: true,  // ✅ دومين خاص
  storeIdentifier: "mystore.com"
}
```

#### **ب. تحميل بيانات المتجر:**

```typescript
// في AppComponent و PublicHomeComponent:

// 1. اكتشف نوع الرابط
const domainInfo = this.domainService.getDomainInfo();

// 2. إذا كان subdomain أو custom domain
if (domainInfo.storeIdentifier) {
  
  // 3. استدعِ API لتحميل بيانات المتجر
  this.storeService.loadStoreBySubdomain(domainInfo.storeIdentifier)
    .subscribe({
      next: (store) => {
        // ✅ تم تحميل المتجر بنجاح
        console.log('المتجر:', store.storeName);
        // عرض صفحة المتجر
      },
      error: (err) => {
        // ❌ المتجر غير موجود
        // إعادة توجيه للمنصة الرئيسية
        this.domainService.navigateToMainPlatform();
      }
    });
}
```

### **2. في الباك إند (ASP.NET Core):**

#### **يجب إضافة API Endpoint:**

```csharp
// في StoreController.cs

[HttpGet("by-subdomain/{subdomain}")]
public async Task<ActionResult<StoreDto>> GetStoreBySubdomain(string subdomain)
{
    // ابحث عن المتجر في قاعدة البيانات
    var store = await _context.Stores
        .Where(s => s.Slug == subdomain || 
                    s.StoreLink == subdomain || 
                    s.CustomDomain == subdomain)
        .FirstOrDefaultAsync();
    
    if (store == null)
    {
        return NotFound(new { 
            message = $"المتجر غير موجود: {subdomain}" 
        });
    }
    
    return Ok(store);
}
```

**مثال على الاستخدام:**
```bash
# طلب:
GET https://dokan-backend-dev.fly.dev/api/Store/by-subdomain/store1

# الرد:
{
  "id": 1,
  "storeName": "متجر محمد",
  "storeLink": "store1",
  "slug": "store1",
  "businessCategory": "Electronics",
  "isActive": true
}
```

## 🔧 **كيف يعمل النظام الآن:**

### **السيناريو 1: زائر يفتح المنصة الرئيسية**

```
1. المستخدم يفتح: https://dokan.shop

2. DomainService يكتشف:
   → isMainPlatform = true
   → storeIdentifier = null

3. التطبيق يعرض:
   → الصفحة الرئيسية للمنصة
   → قائمة المتاجر
   → نموذج التسجيل
```

### **السيناريو 2: زائر يفتح متجر**

```
1. المستخدم يفتح: https://store1.dokan.shop

2. DomainService يكتشف:
   → isSubdomain = true
   → storeIdentifier = "store1"

3. StoreService يستدعي API:
   → GET /api/Store/by-subdomain/store1

4. الباك إند يبحث في قاعدة البيانات:
   → SELECT * FROM Stores WHERE Slug = 'store1'

5. إذا وُجد المتجر:
   → يرجع بيانات المتجر
   → التطبيق يعرض صفحة المتجر
   → يحمّل المنتجات والإعدادات

6. إذا لم يُوجد:
   → يرجع 404
   → التطبيق يعيد التوجيه للمنصة الرئيسية
```

### **الخطوة 3: إضافة Subdomain في Vercel**

#### **الطريقة السريعة (للتجربة):**

1. اذهب إلى: https://vercel.com/osamaazbargas-projects/store-builder
2. اضغط على **Settings**
3. اضغط على **Domains**
4. اضغط على **Add Domain**
5. أدخل: `store1.store-builder-git-dev-osamaazbargas-projects.vercel.app`
6. اضغط **Add**
7. انتظر 1-2 دقيقة

**الآن جرّب:**
```
https://store1.store-builder-git-dev-osamaazbargas-projects.vercel.app
```

#### **الطريقة الدائمة (للإنتاج):**

1. **اشترِ Domain:**
   - مثل: `dokan.shop` من Namecheap ($10/سنة)

2. **أضفه في Vercel:**
   - Settings → Domains → Add: `dokan.shop`
   - Add: `*.dokan.shop` (Wildcard)

3. **أضف DNS Records في Namecheap:**
   ```
   Type: CNAME
   Name: *
   Value: cname.vercel-dns.com
   TTL: Automatic
   ```

4. **انتظر 5-48 ساعة (DNS Propagation)**

5. **بعدها، أي subdomain سيعمل تلقائياً:**
   ```
   https://dokan.shop → المنصة الرئيسية
   https://store1.dokan.shop → متجر 1
   https://store2.dokan.shop → متجر 2
   https://any-name.dokan.shop → أي متجر
   ```

```sql
CREATE TABLE Stores (
    Id INT PRIMARY KEY,
    UserId NVARCHAR(450),
    StoreName NVARCHAR(200),
    StoreLink NVARCHAR(100) UNIQUE,  -- "store1"
    Slug NVARCHAR(100) UNIQUE,        -- "store1"
    CustomDomain NVARCHAR(200) UNIQUE, -- "mystore.com" (اختياري)
    BusinessCategory NVARCHAR(100),
    IsActive BIT DEFAULT 1,
    CreatedAt DATETIME2,
    -- ... باقي الأعمدة
);

-- Indexes للأداء:
CREATE INDEX IX_Stores_Slug ON Stores(Slug);
CREATE INDEX IX_Stores_StoreLink ON Stores(StoreLink);
CREATE INDEX IX_Stores_CustomDomain ON Stores(CustomDomain);
```

## 🔍 **Troubleshooting (حل المشاكل):**

### **المشكلة 1: Subdomain لا يعمل**

**الأعراض:**
- فتح `https://store1.dokan.shop` يعطي 404

**الحل:**
1. تأكد من إضافة الـ subdomain في Vercel Dashboard
2. انتظر 1-2 دقيقة
3. امسح Cache: Ctrl+Shift+R
4. تأكد من أن الـ DNS تم إعداده صحيحاً (إذا كنت تستخدم custom domain)

---

### **المشكلة 2: API يرجع 404**

**الأعراض:**
- Console يعرض: `❌ Store not found`

**الحل:**
1. تأكد من أن الباك إند يحتوي على endpoint:
   ```
   GET /api/Store/by-subdomain/{subdomain}
   ```

2. اختبر API مباشرة:
   ```bash
   curl https://dokan-backend-dev.fly.dev/api/Store/by-subdomain/store1
   ```

3. تأكد من وجود المتجر في قاعدة البيانات:
   ```sql
   SELECT * FROM Stores WHERE Slug = 'store1';
   ```

---

### **المشكلة 3: CORS Error**

**الأعراض:**
- Console يعرض: `Access to fetch has been blocked by CORS policy`

**الحل:**
```csharp
// في الباك إند (Program.cs):
builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowAll", builder =>
    {
        builder
            .AllowAnyOrigin()
            .AllowAnyMethod()
            .AllowAnyHeader();
    });
});

app.UseCors("AllowAll");
```

---

### **المشكلة 4: المتجر لا يظهر**

**الأعراض:**
- الصفحة تُحمّل لكن لا تعرض بيانات المتجر

**الحل:**
1. افتح Console (F12)
2. تحقق من الـ logs:
   ```
   🌐 Domain Analysis: ...
   🏪 Domain Info: ...
   ✅ Store loaded: ...
   ```

3. تأكد من أن `storeIdentifier` ليس `null`
4. تأكد من أن API يرجع بيانات صحيحة
